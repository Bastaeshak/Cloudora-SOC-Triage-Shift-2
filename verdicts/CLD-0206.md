# CLD-0206: Impossible travel: helen.dray@cloudora.io

Engagement: Cloudora · Shift 2 · 2026-08-26
Verdict: False positive · Severity (my rating): Informational (reported Medium)
QA review: Excellent

## Alert
CLD-0206 - Atypical travel: helen.dray@cloudora.io

Rule "Atypical travel" fired after Helen Dray signed in from Manchester (198.51.100.22) at 17:02 UTC Friday and then from Lisbon (198.51.100.140) at 06:19 UTC Tuesday. The Lisbon sign-in succeeded on the first attempt, MFA was satisfied, and the device was a registered iOS device associated with Helen.

## Hypothesis
Malicious: A second party could be using Helen’s credentials from Lisbon, creating a suspicious geographic change from her prior Manchester activity.

Benign: Helen could be legitimately traveling to Lisbon and accessing Cloudora from her registered mobile device during the trip.

## Evidence checked
Reviewed signin_week1.csv and helpdesk_week1.csv.

KQL Query 1:
signin
| where IP in ("198.51.100.22", "198.51.100.140")
| project Timestamp, User, IP, Location, Device, Client, Result, MFA
| order by Timestamp asc

Purpose: Checked whether either IP from the alert was used to access any other Cloudora accounts.

Result: The Lisbon IP 198.51.100.140 appeared only on Helen's account.


KQL Query 2:
signin
| where User == "helen.dray@cloudora.io"
| order by Timestamp asc

Purpose: Reviewed Helen's available sign-in history to compare the Lisbon login with her previous activity.

Result:
- Oct 3, 17:02 UTC - Manchester, Windows/Edge, MFA satisfied.
- Oct 6, 06:19 UTC - Lisbon, registered iOS device, Mobile app, MFA satisfied.


Helpdesk Check:
Reviewed helpdesk_week1.csv for information explaining the Lisbon activity.

Result: HD-5102, opened Oct 1, documented that Helen would be in Lisbon Oct 6-10 and expected to use mobile access only. This matches the location, date, and device type seen in the alert.

## Action
Close as a False Positive with Informational severity. Reference HD-5102, which documented Helen's Lisbon travel from Oct 6-10 and expected mobile-only access before the alert occurred.

No account containment, password reset, or vCISO escalation is required. Re-raise if Helen denies the activity, an unregistered device or unexpected location appears, MFA-related anomalies occur, or other suspicious activity is identified on the account.


## Justification
Oct 1, 11:20 UTC - HD-5102 documented that Helen would be in Lisbon Oct 6-10 and expected mobile access only.

Oct 3, 17:02 UTC - Helen signed in from Manchester using Windows/Edge with MFA satisfied.

Oct 6, 06:19 UTC - Helen signed in from Lisbon using her registered iOS device through the Mobile app with MFA satisfied.

KQL review showed the Lisbon IP 198.51.100.140 only on Helen's account in the available telemetry. The Lisbon sign-in matches the location, dates, and mobile access Helen documented before traveling.

The atypical-travel rule correctly detected a geographic change, but investigation showed the underlying activity was legitimate. Therefore, the alert is a False Positive with Informational severity.

## Tuning note
Consider correlating atypical-travel alerts with documented travel records such as HD-5102. Do not suppress the rule entirely, since unexpected travel from the same account could still indicate compromise.
